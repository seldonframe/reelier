# Reelier Authority Cell on Fly

This directory is a reference topology, not a credential store. Deploy one Authority Cell per project with a separate durable ledger and an egress gateway. The agent runtime may reach its model endpoint and the Authority Cell, but it must not receive provider credentials or direct authenticated provider routes.

Deploy from the repository root with an explicit root build context (`fly deploy . --config ...`) so the manifest's repository-relative `../../../Dockerfile` and root `COPY` inputs resolve together. Supply the app name explicitly and create the `reelier_authority_data` volume first. Deploy `authority-cell-bootstrap.toml` once to initialize the durable directory without exposing HTTP or enabling dispatch. Install the reviewed `authority.yml`, signed jobs, trust, principal registry, and ignored operator configuration on that volume, then redeploy with `authority-cell.toml`. The production process starts authenticated HTTP on port 8080. The host refuses a non-loopback bind unless `authority.yml` contains a durable principal registry or an ingress bearer reference that resolves only inside the Cell.

Do not treat the environment declarations in the manifest as topology proof. The managed release remains blocked until active probes verify the deployed image, actual Fly network-policy digest, credential mounts, Cell-versus-agent provider reachability, raw-write routes, and read coverage.

The three `*.network-policy.json` files are the canonical reference policies. Applying any egress rule makes unmatched egress default-deny on Fly. The agent and Cell policies intentionally omit TCP 443; their external traffic must traverse a separately authenticated gateway. Only the egress-gateway policy permits public HTTPS. Fly policies filter ports, not destination hostnames, and do not cover Fly Proxy traffic, so a policy by itself is not a provider allowlist. Apply policies through Fly's Machines API, restart the Machines as Fly requires, fetch all three deployed policies back, and bind `digestFlyPolicyDeployment(...)` over those read-backs into topology evidence. A local file digest is not deployment evidence.

`agent-runtime.toml`, `authority-cell.toml`, and `egress-gateway.toml` place a closed non-secret probe manifest at `/etc/reelier/topology-probe.json`. The remote runner pins `flyctl`, reads each Machine's actual image digest through the Machines API, then executes fixed `snapshot` and `egress` probes through `fly ssh console`. Snapshots return credential names only, never values. Machine IDs, all three image digests, and the aggregate network-policy digest belong in the ignored operator configuration.

The gateway runs a narrow authenticated HTTP CONNECT service on private port 8443. It accepts only exact declared provider hostnames, resolves and pins a public address, and never receives provider credentials or decrypted provider traffic. Provider TLS terminates end-to-end in the Authority Cell. The Cell's host-owned HTTPS driver uses an explicit configured proxy reference; ambient proxy variables remain ignored. The agent policy does not permit port 8443 or public 443. Enable managed dispatch only after the Cell-originated TLS probe succeeds through this exact route. Proving that the gateway alone can reach a provider is insufficient.

Before enabling managed dispatch, record the image, network policy, connector schema, and provider-surface digests in the signed deployment. Run `reelier authority certify preflight` and `reelier authority certify run --adapter fly-topology` from the Cell. Any topology change invalidates the evidence and current lease.

The reference manifest intentionally contains no tokens, OAuth grants, hostnames with embedded credentials, or provider response bodies.
