# Grok as a universal Reelier channel

Grok is a first-class consumer of the same Reelier authority plane used by Codex, Claude Code, Eve, Hermes, OpenClaw, and future agents. It is not a privileged authority implementation and does not receive a provider-specific Reelier tool bundle.

Grok keeps broad native tools for reads, research, browser preparation, coding, planning, and orchestration. Consequential exits use dynamically discovered, signed Reelier Jobs and Outcomes. A task is governed only when its Outcome can compile a bounded effect and reconcile authoritative provider state; unsupported or partial substrates remain explicit.

## Planned transports

- **Grok Build:** the public Authority MCP surface through an xAI-compatible plugin or skill.
- **Grok Bot:** authenticated HTTPS through a minimal Outcome Console until xAI documents a native Bot integration API.

Both transports must preserve the same catalog, delegation, invocation, lifecycle, coverage, and receipt semantics. Transport code may not hard-code tasks, inject identity, select provider accounts, or upgrade evidence claims.

The v0 Grok fixtures are executable now:

```bash
npm run check:agent-adapter -- conformance/agent-adapter/v0/fixtures/grok-build-observed.json
npm run check:agent-adapter -- conformance/agent-adapter/v0/fixtures/grok-bot-observed.json
```

They perform no live integration or Outcome execution.

## Coverage modes

Observed mode is the initial adoption path. Existing Grok connections and writable browser sessions may remain available, so Reelier proves only the Outcomes routed through it. Topology and completeness stay unchecked.

Enforced mode is a separate activation. It requires fresh evidence that Grok lacks raw provider credentials, equivalent provider-write egress, and writable provider browser sessions for the declared surface. Failed or unavailable evidence refuses activation; it never silently downgrades to observed mode while showing verified completeness.

## Path C dependency

The active Path C worktree owns principals, delegation budgets, job cards, runner registration, provider execution, reconciliation, topology, and receipts. Grok integration begins only after that work publishes Adapter Contract v1 and its golden vectors.

At that point:

1. Bind the adapter to the exact nonzero contract digest.
2. Replace transcript-only checks with black-box MCP and HTTPS probes.
3. Keep every Bot and subagent on a distinct host-authenticated principal session.
4. Begin with a reversible record-state Outcome such as GitHub issue labels or a Slack topic.
5. Expand certification across communications, money, deployments, infrastructure, databases, secrets, information flow, and multi-agent contention.

Refund is one later high-risk certification scenario, not the channel architecture.

## Current xAI evidence

- [Grok Bot](https://x.ai/news/introducing-grok-bot) operates an always-on cloud computer across websites and applications.

This evidence supports treating Grok as a major channel. It does not prove native Grok Bot interception, API availability, credential isolation, or coverage of browser writes.
